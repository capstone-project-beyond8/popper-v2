# Mini Scientist (M0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `popper run examples/student_performance` runs all five phases once (ideation & framing → data → exploration & hypothesis → experiment → publication) and produces `report/paper.tex`, plus `paper.pdf` when tectonic is installed.

**Architecture:** A thin `harness` (config, Bedrock/Fake LLM, subprocess interpreter, write-once run store, journal, budget) sits under a generic `treesearch` stage engine (draft/debug/improve nodes, each a standalone script). Phase packages build stage goals and call the engine; `coordinator` runs the phases in order; `communicate` renders LaTeX with numbers substituted from `results.json`.

**Tech Stack:** Python 3.13, uv, pydantic 2, PyYAML, Jinja2, boto3 (Bedrock Converse), pandas/pyarrow, pytest, ruff, mypy strict.

**Spec:** `docs/ARCHITECTURE.md` (§2–§7) and the `docs/ROADMAP.md` M0 section. Read both before starting.

## Global Constraints

- Code under `src/popper/` stays ≤ 1,400 lines (`wc -l` over `src/popper/**/*.py`). Check it at the end of every task.
- Function packages (`understand`, `ground`, `discover`, `communicate`) import only `popper.harness` and `popper.treesearch`, never each other. Only `coordinator` and `cli` import across them.
- Run files are write-once: `RunStore.write_*` raises `FileExistsError` if the target exists.
- Generated scripts never receive credentials. The interpreter removes `AWS_*` variables and any variable whose name contains `KEY`, `SECRET` or `TOKEN`.
- Every model call and every script execution appends one line to `journal.jsonl`.
- The paper's evidence label is fixed template text: `Exploratory analysis, autonomously generated by Popper. Not confirmed on held-out data.` No model output can change it.
- Tests follow `AGENTS.md`: unit tests for pure logic, integration tests (marker `integration`) for real subprocess and file behaviour, `FakeLLM` only, no provider calls.
- Code, tests and commit messages must not mention milestone numbers or this plan.
- Verification gate after every task: `uv run pytest && uv run ruff check . && uv run mypy`.

## Review Focus

1. **Model reply without a code block.** The node is `buggy` with the analysis "no code block in reply"; the stage continues. Tested in Task 4.
2. **Script writes invalid or wrongly shaped `results.json`.** The node is `buggy` and the next debug step sees why. Tested in Task 4.
3. **No `ok` node by the end of a stage.** `StageFailed` names the stage, the run stops, `run.json` records `status: "failed"` and the stage, and the CLI exits 1 with that message. Tested in Tasks 4 and 7.
4. **Model-written LaTeX that fails to compile.** `paper.tex` is kept, and the CLI prints the `.tex` path and a warning while exiting 0. Tested in Task 6.
5. **Budget reached mid-run.** No further model call is made, `run.json` records `status: "budget_exceeded"`, and the CLI exits 1. Tested in Task 2 (the harness refuses the call) and Task 7 (the run status).

### Task 4: Tree-search engine

**Files:**
- Create: `src/popper/treesearch/__init__.py` (docstring only), `src/popper/treesearch/engine.py`, `src/popper/treesearch/prompts/node.md`, `src/popper/treesearch/prompts/feedback.md`
- Test: `tests/unit/test_policy.py`, `tests/integration/test_stage.py`

**Interfaces:**
- Consumes: `Harness` (Task 2), `run_script`/`ExecResult` (Task 3), `Search` (Task 1).
- Produces (in `engine.py`):
  - `NodeKind = Literal["draft", "debug", "improve"]`
  - `@dataclass Node(id: str, stage: str, parent: str | None, kind: NodeKind, debug_depth: int, dir: Path, code: str, status: Literal["ok", "buggy"], score: float | None, goal_met: bool, analysis: str, results: dict[str, dict[str, Any]], figures: list[str])`
  - `@dataclass(frozen=True) StageSpec(name: str, goal: str, context: str, inputs: Mapping[str, Path], required_outputs: tuple[str, ...], seed_code: str | None = None)`
  - `class StageFailed(Exception)`, carrying `stage: str`.
  - `choose_action(nodes: Sequence[Node], search: Search, rng: random.Random) -> tuple[NodeKind, Node | None]`
  - `select_best(nodes: Sequence[Node]) -> Node | None`
  - `run_stage(h: Harness, spec: StageSpec, rng: random.Random | None = None) -> Node`. It returns the best node or raises `StageFailed`.

`choose_action` implements the policy in ARCHITECTURE §5:

```text
roots = nodes with parent None
if len(roots) < num_drafts: return ("draft", None)
debuggable = buggy nodes with debug_depth < max_debug_depth and no children
best = select_best(nodes)
if debuggable and (best is None or rng.random() < debug_prob): return ("debug", rng.choice(debuggable))
if best: return ("improve", best)
return ("draft", None)
```

**Step procedure** in `run_stage`. Loop `steps_per_stage` times, stopping early when an `ok` node has `goal_met`.

1. Node id is `f"{spec.name}-{i:03d}"` and its dir is `run.path("tree", spec.name, id)`. A debug child has `debug_depth = parent.debug_depth + 1`; drafts and improves have 0.
2. Build the code prompt from `prompts/node.md`. It contains the goal, the context, the input env var names, the required outputs, the `results.json` format (ARCHITECTURE §5), and "save figures as PNG under figures/". It adds the parent's code plus the stderr tail (debug), the parent's code plus analysis (improve), or `seed_code` (draft with seed). Call `h.ask("code", tag=f"code:{spec.name}", ...)`.
3. Extract the first ```python block. If there is none, the node is `buggy` with the analysis `"no code block in reply"` and no execution.
4. Call `run_script`, then journal `event="exec"` with node id, exit code, `timed_out` and seconds.
5. Run the code checks: exit 0, not timed out, every required output exists, and `results.json` is a dict of dicts each having `"value"`. If any fails, the node is `buggy` and the analysis states which check failed plus the stderr tail.
6. Otherwise call `h.ask_json("feedback", tag=f"feedback:{spec.name}", ...)` with `prompts/feedback.md`. It expects `{"is_buggy": bool, "analysis": str, "score": number 1-10, "goal_met": bool}`.
7. Write `meta.json` (everything except code, results and dir) and `analysis.md` to the node dir. Figures are the `figures/*.png` names.
